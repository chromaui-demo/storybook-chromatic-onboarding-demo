# One entry point, five rendering environments

Use this page as presenter notes for the multi-framework demo. Each framework owns a separate
Storybook. The Hub combines their navigation with Storybook `refs`.

| Section          | Local URL        | What to demonstrate                                   |
| ---------------- | ---------------- | ----------------------------------------------------- |
| React            | `localhost:6007` | Component states, callback spies, and visual modes    |
| Next.js          | `localhost:6008` | App Router-aware components and browser interactions  |
| Angular          | `localhost:6009` | Standalone components and validated `@Output` events  |
| Web Components   | `localhost:6010` | Custom elements and bubbling `CustomEvent` payloads   |
| React Native Web | `localhost:6011` | Mobile-sized browser rendering with native primitives |

## Five-minute customer walkthrough

1. Ask which framework and ownership boundaries matter to the customer.
2. Open the equivalent reservation-card story in two relevant frameworks.
3. Show compact, breakpoint, and desktop coverage in the React Storybook.
4. Run one interaction story and connect the assertions to customer risk.
5. Explain that each framework still owns its build, tests, and Chromatic project.

## Important boundaries

- Composition gives teams one discovery URL. It does not merge build, deployment, or test ownership.
- React Native Web provides browser coverage for native primitives. It does not capture native iOS or Android output.
- Responsive visual tests sample chosen widths. They do not test every width in a fluid layout.
