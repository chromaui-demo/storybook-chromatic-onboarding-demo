## Choose the right depth for the customer conversation

- **Core onboarding:** Understand the Storybook 10, MCP, and local-to-CI test value through the React
  project. Every SE starts here.
- **Post-sales technical training:** Start with the customer's current workflow. Use the framework
  examples to diagnose a coverage, ownership, or adoption gap.

Ask which decision matters before you choose a demo path. Use composition only when the customer needs
several independently owned frameworks.

## Five-minute multi-framework walkthrough

1. Ask which framework and ownership boundaries matter to the customer. Stop if composition does not
   support the decision they need to make.
2. Open the equivalent reservation-card story in two relevant frameworks.
3. Show compact, breakpoint, and desktop coverage in the React Storybook.
4. Run one interaction story and connect the assertions to customer risk.
5. Explain that each framework still owns its build, tests, and Chromatic project.

## Important boundaries

- Composition gives teams one discovery URL. It does not merge build, deployment, or test ownership.
- React Native Web provides browser coverage for native primitives. It does not capture native iOS or Android output.
- Responsive visual tests sample chosen widths. They do not test every width in a fluid layout.
