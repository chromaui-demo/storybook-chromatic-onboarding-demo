# One catalog, five rendering environments

This Storybook is the customer-facing entry point. Each sidebar section is a separately built
Storybook composed into this hub with Storybook `refs`.

| Section          | Local URL        | What to demonstrate                                   |
| ---------------- | ---------------- | ----------------------------------------------------- |
| React            | `localhost:6007` | Component states, callback spies, and visual modes    |
| Next.js          | `localhost:6008` | App Router-aware components and browser interactions  |
| Angular          | `localhost:6009` | Standalone components and validated `@Output` events  |
| Web Components   | `localhost:6010` | Custom elements and bubbling `CustomEvent` payloads   |
| React Native Web | `localhost:6011` | Mobile-sized browser rendering with native primitives |

## Suggested customer walkthrough

1. Expand each framework section and open the equivalent reservation-card example.
2. Switch the viewport toolbar between compact, breakpoint, and desktop widths.
3. Open a `Responsive coverage` story and explain that each named mode has its own Chromatic
   baseline.
4. Run an interaction story and step through the user events and assertions.
5. Show that adding or removing an exported story adds or removes an individual test case.

## Important boundaries

- Composition gives the team one branded entry URL, while the referenced Storybooks remain separately
  deployed and separately tested.
- React Native Web is browser coverage. It is not a native iOS or Android screenshot.
- Responsive visual tests sample deliberate widths; they do not continuously sweep every possible
  fluid width.
