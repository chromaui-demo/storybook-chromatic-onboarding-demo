## A simple reflection pattern

Use any of these prompts when a session gives you something worth keeping:

- What customer problem does this capability address?
- What changes for the customer when the capability works well?
- What proof could I show without explaining implementation details?
- What is the most important boundary or tradeoff?
- What question would help me understand whether this matters to a real customer?

## Core onboarding prompts

You can revisit these questions after any of the eight sessions:

1. How would I explain this idea to someone who has never used Storybook?
2. Which customer situation makes the value concrete?
3. Which claim am I least confident making?
4. Which part of the demo proves the claim?
5. What would I ask before recommending an evaluation?

## Post-sales technical training prompts

Technical work needs evidence, but that evidence does not need to live in this repository. A pull
request, Linear issue, Notion page, Obsidian note, or Chromatic build can hold the context.

- What did I change, and why?
- Which checks prove that the change is safe?
- Which customer risk does the implementation reduce?
- What failed, and how did I diagnose it?
- What should the next engineer know before extending this work?

## Ask for useful feedback

- Which explanation made the value clear?
- Where did I become too technical?
- Which claim or boundary needs correction?
- Which question should I have asked earlier?
- Is the proposed next step small enough to evaluate?

If your team wants a worksheet, `progress/TEMPLATE.md` is an optional starting point. Copy its prompts
into the system your team already uses. Do not create a repository file only to satisfy the course.
