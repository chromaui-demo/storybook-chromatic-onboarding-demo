This is a product lab, not a reading list. Over 15 sessions, you will take one React Storybook from
local setup to a customer-ready Chromatic workflow. You will change code, diagnose failed tests,
review visual diffs, connect CI, and finish by leading a mock customer call.

Plan for **60–90 focused minutes per session**. The first ten sessions are the required core. Sessions
11–15 cover composition, scale, upgrade judgment, and a capstone. Work asynchronously, but ask for help
when the evidence stops changing.

## Before Day 1

1. Complete <a href="./?path=/docs/onboarding-start-here-setup--docs" target="_top">setup</a>. The setup page starts with VS Code and Codex installation.
2. Read <a href="./?path=/docs/onboarding-start-here-why-the-workflow-matters--docs" target="_top">why the workflow matters</a> before you configure a tool.
3. Create `progress/<your-github-handle>.md` from the template. Write your first 90-second value explanation.
4. Confirm the training Chromatic project and support contact with the course owner. Never store a token in a tracked file.
5. Complete the sessions in order. Each session ends with working code, evidence, a customer explanation, and a focused commit.
6. Finish with the <a href="./?path=/docs/onboarding-reference-capstone-rubric--docs" target="_top">mock-demo capstone</a>.

If you run the course, complete the <a href="./?path=/docs/onboarding-reference-facilitator-setup--docs" target="_top">facilitator setup</a> before you assign Day 1.

## The customer you will carry through the course

You are advising **Trailhead Travel**, a fictional mid-sized enterprise. Its design-system team uses
React. Product teams also ship Next.js, Angular, Web Components, and React Native Web. UI coverage is
inconsistent, reviews are slow, and teams cannot discover all components in one place.

The goal is not to memorize product features. By the capstone, you should be able to discover the
customer's risk, choose a useful demo path, explain tradeoffs, recover from a failure, and recommend a
measured next step. You will practice two call types: a presales evaluation and a postsales adoption
conversation.

## Call a day done when

A session is complete when all five statements are true:

- You completed the requested work on your branch.
- The verification commands pass, or you recorded a reproducible product issue.
- Your progress file contains the requested URL, screenshot, terminal result, or commit SHA.
- You can explain the customer value and the product boundary in your own words.
- You committed a focused checkpoint without secrets or generated output.

Official docs explain each feature. This lab gives you a customer, a safe practice environment, and a
repeatable path from discovery to evidence.
