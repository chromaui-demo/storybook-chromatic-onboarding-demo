## Three themes connect the whole course

Every learner must be able to explain and prove these themes:

1. **Why upgrade to Storybook 10?** Teach the platform value, the ESM and runtime boundary, and a safe
   evaluation path.
2. **Why use Storybook MCP?** Show how documented components and stories give coding agents grounded
   context. State that the current AI capabilities are preview and the docs toolset is React-only.
3. **Why use Storybook Test locally and in CI?** Show the same story-defined browser test beside the
   component and on a pull request.

Chromatic connects the themes with published visual evidence and a clear review decision.

## The customer you will carry through the course

You are advising **Trailhead Travel**, a fictional mid-sized enterprise. Its design-system team uses
React. Product teams also ship Next.js, Angular, Web Components, and React Native Web. UI coverage is
inconsistent, reviews are slow, and teams cannot discover all components in one place.

During core onboarding, Trailhead is deciding whether the current Storybook platform and workflow fit
its needs. During technical training, Trailhead already uses Storybook or Chromatic and needs stronger
adoption, coverage, or governance.

## How to use each session

Each core onboarding session follows the same learning pattern:

1. Understand why the customer cares.
2. Learn the product model and its boundary.
3. Explore the proof in the prepared demo.
4. Consider thoughtful discovery questions.
5. Practice responding to a realistic customer question.

You can keep notes in Notion, Obsidian, Linear, a document, or nowhere at all. The course does not
require a repository progress file. Use the note-taking system that helps you prepare for customers.
