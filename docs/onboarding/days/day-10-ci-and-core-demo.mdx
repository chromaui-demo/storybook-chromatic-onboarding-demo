## Put the workflow on rails

1. Inspect the repository's Chromatic workflow. If the facilitator has not added it yet, create
   `.github/workflows/chromatic.yml` with:
   - checkout using `fetch-depth: 0`;
   - Node 20 and the pnpm version from `packageManager`;
   - `pnpm install --frozen-lockfile`;
   - the token from `${{ secrets.CHROMATIC_PROJECT_TOKEN }}`;
   - `workingDir: packages/react`, so the action uses that package's Storybook build script and config;
   - a `push` trigger for `main` and learner branches.
2. Do not enable automatic acceptance, `exitZeroOnChanges`, or TurboSnap for learner branches.
3. Push your branch and follow the action, Chromatic build, UI Tests, and UI Review checks from commit
   to result. Verify the build maps to the pushed commit rather than an ephemeral merge commit.
4. Ask the facilitator before changing branch protection or required checks. Reading and explaining
   policy is part of this day; changing repository-wide policy is not.
5. Deliver the five-minute core demo below to a teammate or record it for asynchronous feedback.

## Run the five-minute version

1. State the customer problem in the language of your chosen call.
2. Show an editable React story and its Autodocs.
3. Switch among deterministic MSW states.
4. Run an interaction and accessibility test.
5. Open a Chromatic diff, explain the baseline, and show the passing CI result.
6. Close with a practical next step:
   - **Presales:** name what the customer should validate in a time-boxed evaluation.
   - **Postsales:** name the coverage gap, the smallest change, and the evidence that would show it helped.

## Check the handoff from Git to Chromatic

- The workflow uses full Git history and a repository secret.
- The branch build is attached to the expected commit and surfaces its checks.
- Your progress file names the call you practiced, contains feedback on the five-minute demo, and
  records one improvement for the capstone.

## Be ready for the ancestry question

Be ready when someone asks: **Why do we recommend building `main`, and why are push-based workflows
often safer for baseline ancestry than default pull-request merge commits?**
