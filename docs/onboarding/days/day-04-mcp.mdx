## Read the MCP model

- [Sharing an MCP server](https://storybook.js.org/docs/10.5/ai/mcp/sharing)

Storybook 10.5 MCP is preview and React-only for manifest-backed knowledge. A composed Angular or Web
Components Storybook may still appear in the sidebar without offering equivalent manifest context.

## Connect Codex to the live Storybook

1. Start the React Storybook and keep it running:

   ```sh
   pnpm --filter @demo/react storybook
   ```

2. Connect Codex to `http://localhost:6007/mcp`. Adjust the port if Storybook selected another.
   Use Codex's documented project-level MCP configuration so the connection belongs to this
   repository rather than every project on your machine.
3. Ask Codex to list documented components, retrieve `ReservationCard` details, and identify the
   available stories. Verify its answers in Storybook.
4. Before Codex writes or modifies a story, require it to retrieve Storybook's current story-writing
   instructions. Ask Codex to add one bounded story using only documented props.
5. Ask Codex to run the affected story tests through MCP. Compare the result with the Interactions panel and the
   terminal test run.
6. Add repository instructions that require docs lookup before using component props, current
   story instructions before authoring, and story tests after UI changes. Keep the wording independent
   of a single agent product.

## Prove that Codex is grounded

- The local MCP connection responds while Storybook is running and fails predictably when it is not.
- Codex cites actual component and story knowledge instead of inferring props from display names.
- The new or changed story passes MCP and terminal verification.

## Practice the SE answer

Practice the boundary out loud: **What does MCP know, what is still local, and why is a published docs
endpoint not a remote code-editing service?**

<details>
<summary>Recovery</summary>

If the endpoint does not respond, confirm the React port, verify `@storybook/addon-mcp` is in
the React add-on list, restart Storybook, and reconnect. Do not point Codex at the composition Hub
unless you intentionally want the host's knowledge boundary.

</details>
