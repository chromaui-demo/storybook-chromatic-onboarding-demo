## Plan on 75 minutes

- 15 minutes: read
- 20 minutes: connect and smoke-test
- 30 minutes: grounded authoring exercise
- 10 minutes: verify and explain

## Open the MCP docs

- [Using Storybook with AI](https://storybook.js.org/docs/10.5/ai)
- [MCP server overview](https://storybook.js.org/docs/10.5/ai/mcp/overview)
- [MCP API](https://storybook.js.org/docs/10.5/ai/mcp/api)
- [Sharing an MCP server](https://storybook.js.org/docs/10.5/ai/mcp/sharing)

Storybook 10.5 MCP is preview and React-only for manifest-backed knowledge. A composed Angular or Web
Components Storybook may still appear in the sidebar without offering equivalent manifest context.

## Connect the agent to the live Storybook

1. Start the React Storybook and keep it running:

   ```sh
   pnpm --filter @demo/react storybook
   ```

2. Connect your agent to `http://localhost:6007/mcp`, adjusting the port if Storybook selected another.
   Use your agent's documented project-level MCP configuration so the connection belongs to this
   repository rather than every project on your machine.
3. Ask the agent to list documented components, retrieve `ReservationCard` details, and identify the
   available stories. Verify its answers in Storybook.
4. Before asking it to write or modify a story, require it to retrieve Storybook's current story-writing
   instructions. Ask it to add one bounded story using only documented props.
5. Ask MCP to run the affected story tests. Compare the tool result with the Interactions panel and the
   terminal test run.
6. Add repository agent instructions that require docs lookup before using component props, current
   story instructions before authoring, and story tests after UI changes. Keep the wording independent
   of a single agent product.

## Make sure it is actually grounded

- The local MCP connection responds while Storybook is running and fails predictably when it is not.
- The agent cites actual component/story knowledge rather than inferring props from display names.
- The new or changed story passes MCP and terminal verification.

## Tell the customer why this matters

Practice the boundary out loud: **What does MCP know, what is still local, and why is a published docs
endpoint not a remote code-editing service?**

<details>
<summary>Recovery</summary>

If the endpoint does not respond, confirm the actual React port, verify `@storybook/addon-mcp` is in
the React add-on list, restart Storybook, and reconnect. Do not point the agent at the composition hub
unless you intentionally want the host's knowledge boundary.

</details>
