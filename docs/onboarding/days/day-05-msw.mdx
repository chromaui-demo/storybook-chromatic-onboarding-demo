## Make every response state repeatable

1. Install MSW in the React workspace and generate its worker:

   ```sh
   pnpm --filter @demo/react add -D msw msw-storybook-addon
   pnpm --filter @demo/react exec msw init public --save
   ```

2. Expose `packages/react/public` through `staticDirs` in `.storybook/main.ts`. Initialize MSW and add
   its loader in `.storybook/preview.tsx` following the current official guide.
3. Create `AvailabilityPanel.tsx`. It should request
   `GET /api/properties/:propertyId/availability` and render a stable loading state followed by
   available dates, an empty result, or an error message.
4. Create stories for `LoadingThenAvailable`, `NoAvailability`, and `ServiceError`. Put default handlers
   at the narrowest level that avoids duplication, then override them per story.
5. Ensure every request is intercepted. An unhandled request should be treated as a test failure or a
   deliberate, documented exception.
6. Run Storybook with the browser network panel open and prove that no real service is contacted.

## Confirm every response state

- Refreshing each story produces the same state.
- Success, empty, and error paths can be opened directly by story URL.
- The service worker is served by Storybook, but generated build output remains untracked.
- Type checking, story tests, and the static build pass.
